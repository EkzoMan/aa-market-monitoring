## Ключевое требование

Все формулы — в `marketmonitoring/calc/engine.py` как **чистые функции**: без обращений к БД и сети. Вход — примитивы и `Decimal`. View и tasks только вызывают их.

## Формулы (источник истины — §6 ТЗ, эталонный пример §6.11 — обязателен в тестах)

- $K=\min_i \lfloor A_{t_i}^{S_i}/q_i \rfloor$; узкие места — все $i$ с $\text{fits}_i=K$ (в UI до 5 + «и ещё N»).
- Статусы по приоритету: `NO_DATA` → `HULL_MISSING` → `DEFICIT` → `OK`. При `NO_DATA` дефицит и стоимость НЕ рассчитываются.
- $D_i=\max(0,\ N q_i - A)$; по каждому фиту независимо (никакого схлопывания потребностей).
- `unit(D)`: покрывающий лот, иначе средневзвешенная до покрытия, иначе `NOT_COVERED` (тогда стоимость только за `covered`, `shortfall` отдельно).
- `cost_i = round((unit·(1+m) + c_del·pvol) · D_i)` ROUND_HALF_UP до целого ISK; доставка без наценки; pvol = packaged_volume, при 0 → volume, при 0 → доставка 0.
- `Total` = сумма уже округлённых строк (должна совпадать с CSV).
- OVERPRICE: `unit > ref·(1+τ/100)`, `ref` — минимальная sell Jita. Оверпрайс-позиция входит в итог.

## Запреты

- `float` где угодно в расчётах денег — только `Decimal`, сравнения цен без float.
- `order_range` заказа при агрегации не используется (заказ лежит на своей станции).
- Строгий scope: `station` — только заказы этой станции; `system`/`region` — NPC-станции + включённые структуры.
