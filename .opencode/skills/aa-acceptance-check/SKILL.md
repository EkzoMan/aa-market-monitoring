## Definition of Done

Все 16 критериев §19 выполняются; тесты §18 зелёные; миграции применяются на чистой БД AA 5; README описывает установку, привязку провайдеров, настройку наценки/порогов, диагностику `NO_DATA`; в коде нет обращений к ESI из веб-запросов.

## Чеклист §19 (прогонять по пунктам)

1. EFT из игры (вкл. русский клиент) разбирается полностью; корпус, дроны, cargo присутствуют.
2. Дефицит по компоненту → «12 из 30», статус `DEFICIT`, узкое место ровно этот компонент.
3. Нет корпуса → `HULL_MISSING` независимо от остальных позиций.
4. Scope `station`: заказы других станций системы/региона не учитываются.
5. Два фита с общим компонентом — дефицит независимо (две строки, без схлопывания).
6. Цена покрытия: лот ≥ D → его цена; иначе средневзвешенная; иначе `NOT_COVERED` + `shortfall`.
7. `unit > ref·(1+τ/100)` → `OVERPRICE`, виден в UI и не исключает позицию из итога.
8. Формула `cost` §6.9; сумма строк = `Fit.total_cost` = сумма CSV.
9. Ручной запуск не порождает уведомлений о дефиците; beat — порождает.
10. Повтор о неизменном дефиците ≤ 1 раз / 2 ч; изменение состояния — сразу.
11. 403 → cooldown 60 мин, переход на другого провайдера; 3 сбоя → `disabled` + алерт.
12. Отключение локации удаляет её кэш задачей `cleanup_orphan_cache`.
13. Multibuy импортируется в игру (`Name<TAB>Qty`), только английские имена.
14. `_view` не меняет данные; `_edit` не видит лог синков в `/admin/`.
15. `SyncRun` фиксирует каждый прогон: триггер, статус, число локаций.
16. Настройки меняются без перезапуска beat, применяются к следующему прогону.

## Команды перед сдачей

- `python manage.py makemigrations --check`
- полный прогон тестов (без сети)
- линт (black, isort; line-length 120)
- grep-проверка: нет `print(` в продакшн-коде, нет вызовов ESI в `views/`, нет `float` в денежных расчётах `calc/`
