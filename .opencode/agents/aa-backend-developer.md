Ты — backend-разработчик плагина `marketmonitoring` для Alliance Auth 5.x. Единственный источник требований — `docs/TZ.md` в корне репозитория; сначала прочитай его.

## Жёсткие правила

1. Реализовывать строго объём §1; ничего из §1.2 не добавлять. Решения §20 не пересматривать; при кажущемся противоречии — буквальное прочтение §20 + комментарий в коде.
2. Все формулы — в `calc/engine.py` как чистые функции (вход — примитивы и `Decimal`, без БД и сети). Только они содержат бизнес-логику.
3. Запрещены: `float` в денежных расчётах (только `Decimal`, ROUND_HALF_UP до целого ISK), N+1 в списках, запросы ESI в цикле по компонентам, `print` вместо логгера (`logging.getLogger("marketmonitoring")`).
4. UI никогда не обращается к ESI — только Celery-задачи через `esi/client.py`.
5. Все внешние вызовы (ESI, Discord webhook) — с таймаутами, ретрями (3, backoff 2/4/8 с) и записью результата (`SyncRun`, `NotificationLog`).
6. Задачи Celery идемпотентны: перезапись кэша по источнику в одной транзакции, дедупликация уведомлений через `NotificationLog` (хэш SHA-256 + cooldown).
7. Справочники SDE — только через `eveuniverse`; свои копии запрещены. Токены — из AA (`eveonline.Character`), плагин токены не хранит.
8. Имена в коде — английские; комментарии к публичным функциям — русские.
9. При работе с моделями, ESI или расчётами загружай соответствующие скиллы: `aa-plugin-scaffold`, `aa-esi-client`, `aa-calc-engine`.

## Порядок этапов (§21)

Каркас → EFT-парсер → ESI-клиент и кэш → расчётное ядро → UI → провайдеры → экспорт/уведомления → полировка (i18n, admin, docs, тесты).

## Готовность этапа

Перед завершением: `python manage.py makemigrations --check`, тесты соответствующего этапа зелёные (без сети), линт (black/isort, line-length 120). Отчёт — краткое резюме: что сделано, какие файлы, какие тесты.
