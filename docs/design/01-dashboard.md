## Компоновка

1. **Шапка-строка**: заголовок + (edit) кнопка «Refresh now» + индикатор поллинга.
2. **Сводная панель** (`card card-primary`, col-md-4):
   - «Total to buy» — крупно (`.h3.mm-num`), сумма только по фицам без NO_DATA;
   - подпись «NO_DATA fits are not included in the sum. (3)»;
   - отдельные счётчики доступных кораблей: `∑C` (контракты), `∑K` **per fit**
     и `∑(C+K)`; в суммы входят только фиты с известными C и K;
   - счётчики: HULL_MISSING (danger-текст), оверпрайс-позиций суммарно,
     компонентов с дефицитом → ссылка на Components;
   - «Last checked», «Last sync» — мелкий `.text-body-secondary`.
3. **Фильтры** (col-md-8): один `<form method=get>`, selects: status / scope /
   bottleneck / sort. Кнопка Apply (`btn-outline-secondary`). Сортировка — select
   с вариантами по возрастанию/убыванию (текущая реализация сохраняется).
4. **Таблица фитов**: `table-sm table-hover`, sticky thead. Первая колонка — чекбокс выбора фита для сводной закупки (в заголовке — «select all»). «Collectability (C+K)» — единственная колонка итогового числа доступных кораблей: `C+K` из N с прогресс-баром, цвет которого берётся из общего статуса `ships_status_cache` (`ok`/`deficit`/`no_data`); бейдж того же статуса показан в колонке «Ships status». При `no_data` любого источника C или K — «—», прогресс не рисуется, рыночный `status_cache` в этой колонке не используется (§6.13, решения №40, №43). Отдельная колонка «Ships total (C+K)» удалена как дубль. Раздельные значения остаются в «Ships on contracts» (C/N) и «Ships from market (K/N, per fit)»; сводка по-прежнему показывает ∑C, ∑K **per fit** и ∑(C+K) только по фитам с известными обеими величинами. Столбцы «Total to buy» и «Overprice» из таблицы удалены по требованию пользователя; стоимость докупки и оверпрайс остаются доступны в карточке фита и в экспорте закупки.
5. **Сводная закупка**: в шапке карточки Fits — `Copy multibuy` и `Selected .txt` (доступны `view`). Кнопки работают с отмеченными чекбоксами фитами: сервер складывает $D_i$ одинаковых типов, формирует `Name<TAB>Qty` на английском и возвращает текст для Clipboard API/files. При пустом выборе — inline-подсказка «Select at least one fit.», при пустом списке закупки — «Nothing to buy for the selected fits.». Состояния копирования повторяют карточку фита (`07-states.md` §1.1) с fallback на `execCommand`.

## Состояния

- Пусто (нет фитов): empty state, см. `07-states.md` §Empty.
- Поллинг: кнопка disabled, spinner в статусе, авто-reload при успехе, alert-danger
  при ошибке (см. `07-states.md` §Polling).
- Общий статус кораблей: в колонке Collectability показываются `ships_total` и бейдж
  `ships_status_cache` (в колонке «Ships status»); при `no_data` — «—» вместо C+K. Число агрегатного
  дефицита `N−(C+K)` в строке дашборда не выводится — оно показывается в карточке
  фита (подробнее — `07-states.md` §1.1).
- «Обновить сейчас» — **скрыт** для `view` (уже так: `{% if can_edit %}`).

## Мобильная деградация (приоритет 2)

- Сводка и фильтры — в столбец (col-12).
- Таблица — горизонтальный скролл `.table-responsive` (не карточная трансформация:
  строк много, скролл предсказуем). Первые 3 колонки остаются читаемыми при повороте.
