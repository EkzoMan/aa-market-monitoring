## Шапка

- Breadcrumb «← Dashboard» и название фита в основной карточке.
- Блок **Ships on contracts** (над основной карточкой): чип контрактного статуса,
  `C/N` + прогресс; при `C < N` — бейдж «Missing N ships», при `no_data` —
  `alert-secondary` с причиной и ссылкой на провайдеров (для `edit`).
- Блок **Available ships**: отдельный бейдж `ships_status_cache`
  (`ok` / `deficit` / `no_data`), отдельные числа `C` (контракты), `K` (рынок,
  подпись **per fit**) и `C+K`. При `deficit` — «Missing N ships» с агрегатным
  дефицитом `N−(C+K)`; при `no_data` любого источника — «—» вместо чисел.
- Основная карточка: чип рыночного статуса + «K из N» + прогресс (тот же паттерн,
  что на дашборде, крупнее — прогресс `height: .75rem`, ширина 160px).
- Сумма докупки крупно. При NO_DATA — «—» + баннер.
- Счётчики: оверпрайс-позиций, строк с дефицитом.
- Рыночный, контрактный и общий бейджи не подменяют друг друга; новый статус не
  меняет `D_i`, `unit`, `cost` и экспорт закупки.
- Кнопки:
  - **Copy multibuy** (`btn-primary`, иконка copy) — Clipboard API, toast «Copied»;
  - **.txt / .csv** (`btn-outline-secondary` dropdown или две кнопки) — обычные ссылки
    на `export_txt`/`export_csv`;
  - **edit-группа** (`can_edit`): Edit → `fit_update`, Delete → `fit_delete`
    (danger-outline). Для `view` — не рендерятся вовсе.

## Таблица компонентов (§14.1)

Колонки (порядок фиксирован): Component (имя + «×qᵢ per fit» мелким текстом) ·
Scope · Req (N·qᵢ) · Avail (A) · Deficit (Dᵢ) · unit · ref · Cost · Badges.

- Числа — `.mm-num` right; `unit`/`ref` — целые ISK с разделителями.
- **HULL-строка (решение):** `td:first-child`-строка получает класс `.mm-hull-row`:
  - `border-left: 3px solid var(--bs-primary)` (акцентная полоса слева),
  - `font-weight: 600` на имени,
  - фон `var(--bs-tertiary-bg)` — мягче зебры, не ломает выравнивание чисел;
  - имя корпуса подписано чипом `HULL` (`text-bg-primary`, мелкий).
- Бейджи OVERPRICE/NOT_COVERED — в последней колонке «Badges» (не смешиваются с числом
  стоимости: легче сканировать). При HULL_MISSING строка корпуса получает бейдж
  `NOT_COVERED`, если недоступна.
- Итоговая строка `tfoot`: «Total» + сумма = `Fit.total_cost`.

## Экспорт

- Multibuy: только строки с Dᵢ>0, английские имена, сортировка по имени (case-insens).
- Toast всегда «Copied» (en). См. `07-states.md` §7.

## NO_DATA

- Баннер над таблицей; в строках компонентов цифры заменяются на «—» (или таблица
  заменена баннером + списком имен компонентов без цифр — рекомендация: **оставить
  таблицу с «—»**, закупщику виден состав).
- При `no_data` в любом источнике (C или K) в шапке вместо `C/N`, `K/N` и итога
  `C+K` показывается «—», общий бейдж — `no_data`. Рыночный и контрактный бейджи
  остаются на месте, чтобы была видна причина; агрегатный дефицит не выводится.
- Колонки таблицы компонентов не меняются: `D_i`, `unit`, `ref`, `cost` и бейджи
  `OVERPRICE` / `NOT_COVERED` по-прежнему определяются рыночными данными (§6.5–§6.9).

## Производительность

- ≤ 500 мс: таблица 20–60 строк, ноль per-row JS; только один скрипт копирования.
